# Configuration

Toute la configuration passe par des variables d'environnement (fichier `.env` avec docker-compose).

## Référence

| Variable | Défaut | Description |
|---|---|---|
| `COMMUN_DATA_DIR` | `~/.commun` (`/data` en Docker) | Répertoire de données : base SQLite `commun.db` |
| `COMMUN_PORT` | `3000` | Port publié par docker-compose |
| `COMMUN_MIGRATIONS_DIR` | auto | Dossier des migrations Drizzle (fixé dans l'image Docker, ne pas modifier) |
| `COMMUN_S3_ENDPOINT` | — | Endpoint S3-compatible (vide pour AWS ; `http://minio:9000` avec le profil MinIO) |
| `COMMUN_S3_REGION` | `fr-par` | Région S3 |
| `COMMUN_S3_BUCKET` | — | Bucket des médias (requis pour les médias — S3 est le seul backend, iso legacy) |
| `COMMUN_S3_ACCESS_KEY` / `COMMUN_S3_SECRET_KEY` | — | Identifiants S3 |

## Sécurité

- L'authentification est iso legacy : token de session opaque transmis en `Authorization: Bearer` (pas de cookie), stocké hashé côté serveur, révocable — il n'y a **pas** de secret de session à configurer.
- Les tokens API (build du site) sont affichés une seule fois à la création et stockés hashés ; révoquez-les depuis l'admin. Les routes legacy `/api/v1/content/*` acceptent aussi l'en-tête `Authorization` brut envoyé par les builds actuels.
- **CORS** : ouvert (`*`), sans risque car l'auth est un en-tête Bearer jamais attaché automatiquement par le navigateur.
