# Configuration

Toute la configuration passe par des variables d'environnement (fichier `.env` avec docker-compose).

## Référence

| Variable | Défaut | Description |
|---|---|---|
| `COMMUN_DATA_DIR` | `~/.commun` (`/data` en Docker) | Répertoire de données : base SQLite `commun.db` + médias locaux |
| `COMMUN_ADMIN_EMAIL` | — | Email du premier admin ; un lien d'invitation est affiché dans les logs au premier boot d'une instance vierge |
| `COMMUN_PORT` | `3000` | Port publié par docker-compose |
| `COMMUN_MIGRATIONS_DIR` | auto | Dossier des migrations Drizzle (fixé dans l'image Docker, ne pas modifier) |
| `COMMUN_S3_ENDPOINT` | — | Endpoint S3-compatible (vide pour AWS ; `http://minio:9000` avec le profil MinIO) |
| `COMMUN_S3_REGION` | `fr-par` | Région S3 |
| `COMMUN_S3_BUCKET` | — | Bucket des médias — sa présence (avec les identifiants) active le driver S3 |
| `COMMUN_S3_ACCESS_KEY` / `COMMUN_S3_SECRET_KEY` | — | Identifiants S3 |

::alert{type="warning"}
En production (`NODE_ENV=production`), l'instance **refuse de démarrer** si une variable `COMMUN_*` contient une valeur d'exemple (`changeme`, `example`…). Aucun secret n'a de valeur par défaut.
::

## Sécurité

- Les sessions sont des tokens opaques stockés hashés (cookie `httpOnly`) — il n'y a **pas** de secret de session à configurer.
- Les tokens API (build du site) sont affichés une seule fois à la création et stockés hashés ; révoquez-les depuis l'admin.
- Derrière un reverse-proxy, transmettez `X-Forwarded-For` pour que le rate-limiting des formulaires citoyens soit correct.
