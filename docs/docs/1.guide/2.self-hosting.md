# Auto-hébergement

Une instance Commun complète tient dans un `docker compose up`. Comptez une dizaine de minutes.

## Prérequis

- Un serveur avec Docker et Docker Compose (2 Go de RAM suffisent largement pour une commune).
- Un nom de domaine pointant vers le serveur (recommandé), avec un reverse-proxy TLS (Caddy, nginx…).

## Installation

```sh
git clone https://github.com/commun-app/commun && cd commun
cp .env.example .env
# Éditez .env : renseignez au minimum COMMUN_ADMIN_EMAIL
docker compose up -d
```

Vérifiez l'état :

```sh
curl http://localhost:3000/health
# {"status":"ok","service":"@commun/api", ...}
```

## Premier compte administrateur

Au premier démarrage d'une instance vierge, un **lien d'invitation à usage unique** est affiché dans les logs pour l'email configuré :

```sh
docker compose logs api
```

Consommez ce lien pour définir votre mot de passe et activer le compte. Le mécanisme est inerte dès qu'un utilisateur existe — il ne peut pas être rejoué.

## Stockage des médias

Par défaut, les médias sont stockés **sur le disque de l'instance** (volume `commun-data`) — aucune dépendance externe.

Pour un stockage S3-compatible, deux options :

1. **Service externe** (Scaleway Object Storage, Garage…) : renseignez `COMMUN_S3_*` dans `.env`.
2. **MinIO embarqué** : `docker compose --profile s3 up -d`, puis pointez `COMMUN_S3_ENDPOINT=http://minio:9000` avec le bucket et les identifiants MinIO.

## Mise à jour

```sh
git pull
docker compose build && docker compose up -d
```

Les migrations de base de données s'appliquent automatiquement au démarrage.
