# Sauvegarde et restauration

Une instance Commun = **un répertoire de données**. C'est l'un des bénéfices du single-tenant SQLite : la sauvegarde est triviale.

## Ce qu'il faut sauvegarder

| Élément | Emplacement |
|---|---|
| Base de données | `$COMMUN_DATA_DIR/commun.db` (+ fichiers `-wal`/`-shm`) |
| Médias (driver local) | `$COMMUN_DATA_DIR/media/` |
| Configuration | votre fichier `.env` |

Avec docker-compose, tout vit dans le volume `commun-data`.

## Sauvegarde à chaud

SQLite en mode WAL se sauvegarde proprement via l'API de backup — sans arrêter l'instance :

```sh
docker compose exec api bun -e '
import { Database } from "bun:sqlite";
const db = new Database("/data/commun.db");
db.exec(`VACUUM INTO "/data/backup-${new Date().toISOString().slice(0,10)}.db"`);
' && docker compose cp api:/data/backup-$(date +%F).db ./backups/
```

Puis copiez le répertoire `media/` (rsync, restic…). Planifiez le tout en cron quotidien.

## Restauration

```sh
docker compose down
# Remplacez commun.db par la sauvegarde (supprimez les -wal/-shm), restaurez media/
docker compose up -d
```

C'est tout — pas de serveur de base de données à resynchroniser.
